# 机柜视界

机柜台账与容量规划桌面工具。单机离线运行，数据存在本地一个 SQLite 文件里。

面向网络工程师：管机柜、管设备位置、看还剩多少 U 和多少功率、提前预留位置。

## 运行

```bash
pip install -r requirements.txt
python main.py
```

指定数据库文件（多套台账或打开备份）：

```bash
python main.py --db D:/data/我的机房.db
```

首次启动会自动生成一份示例数据（1 个机房、5 个机柜、18 台设备），方便先看效果。在「设置」页可以一键清空。

## 打包 exe

```bash
pip install pyinstaller
python tools/make_icon.py          # 生成 assets/app.ico，改过配色才需要重跑
pyinstaller build.spec --noconfirm
```

产物 `dist/机柜视界.exe`，约 44MB，单文件免安装，拷到没装 Python 的机器上双击就能跑。

数据库不在 exe 里，运行时落在 `%APPDATA%\机柜视界\cabinet_vision.db`，所以升级时直接覆盖旧 exe，台账不会丢。同样支持 `--db` 指定库文件。

`build.spec` 开头的 `ONEFILE` 改成 `False` 会出目录版：启动快几秒，代价是一堆文件。单文件版每次启动要先解包到临时目录，冷启动约 2 到 4 秒。

## 功能

**机柜视图** — 二维正视图，U 位从底部往上编号（1U 在最下面）。设备按类型配色，拖拽即可换位置或跨机柜搬迁，落点实时校验，放不下会显示红色提示。支持单柜和整列并排两种模式，可导出 PNG / PDF 贴机柜门或写方案。

**设备台账** — 大表格，按机房 / 列 / 机柜 / 类型 / 状态 / 责任人 / 项目多条件筛选，关键字搜设备名、IP、型号、序列号、资产号。支持批量修改、批量上下架、批量删除。筛选结果可直接导出 Excel。

**复制设备** — 同型号设备往往一大片，选中一台点「复制设备」，弹出的新增框已按原机预填。型号、厂商、类型、U 数、功耗、承重、责任人、项目、备注照抄；SN、资产号、管理 IP 是每台唯一的，留空待填。名字自动递增且跳过已占用的编号（`SW-CORE-01` 下一个是 `SW-CORE-03`，如果 `-02` 已存在），位数保持不变（`PDU-09` → `PDU-10`）；末尾没数字就加「-副本」。U 位不带过来 —— 原位置已被占用，抄过来必然冲突，所以副本先进待上架，再拖到想放的地方。机柜保留，方便就近放。机柜视图里右键设备也有这个入口。

**设备类型自定义** — 内置交换机、路由器、防火墙等 11 种，机房里的东西不止这些，所以类型清单可以自己维护。改完立刻生效：台账的类型筛选、新增设备的下拉、机柜图配色和图例、Excel 导入模板的说明都跟着变。

两个入口。录设备时最常用的是**类型下拉最下面的「＋ 新增类型…」**：发现清单里没有这个类型，当场加完自动选上接着录，不用退出去。批量修改的类型下拉里也有同一个入口。要成批整理类型清单（改名、换配色、删掉不用的）则去**设置页的类型表**，那里能看到每种类型下面挂了多少台设备。

类型清单存在库里，跟着 .db 文件走，所以备份包含它、换库会换成新库的那一份。几条规则：改名会同步更新台账里用这个类型的设备（不会丢数据）；删类型时那些设备归到「其他」，设备本身不动；「其他」是兜底类型，不能删也不能改名，识别不出的类型都要有地方归，但配色可以改。删过内置类型也不要紧，「恢复默认类型」会把缺的补回来，自己加的类型和改过的配色都不动。清空数据不会清掉类型配置 —— 那是配置而不是台账。

**容量规划** — 机房 / 列 / 机柜三级汇总 U 位、功率、承重使用率，超限标红。U 位预留用来提前占位排布新设备，预留在容量里单独统计，可以一键落实成真实设备。

**导入导出** — Excel 批量导入，表头支持常见别名（「设备名称」「主机名」都认）。导入分两步：预检在事务里真跑一遍再回滚，同一批数据内部的 U 位重叠也能提前发现，不会导一半污染台账。导出的清单和导入模板列结构一致，改完能直接导回来。

**备份** — 所有数据在一个 .db 文件里，复制走就是完整备份。设置页可以备份、切换数据库、清空数据。

## 项目结构

前后端分离，界面不直接碰 SQL。

```
backend/                 后端，不依赖 PyQt，可独立测试
  schema.py              建表语句与迁移
  database.py            连接、事务、迁移、备份
  models.py              DTO（dataclass），前后端共用
  constants.py           状态、配色等领域常量 + 设备类型运行时注册表
  errors.py              业务异常
  repositories/          只写 SQL，负责行与 DTO 转换
  services/              业务规则
    occupancy.py         U 位占用与冲突校验（核心）
    place_service.py     机房 / 列 / 机柜
    device_service.py    设备增删改、上下架、连接关系
    device_type_service.py  设备类型清单，增删改与注册表同步
    capacity_service.py  机柜布局、预留、容量汇总
    excel_service.py     模板、导入、导出
    seed_service.py      示例数据
  api.py                 Backend 门面，前端唯一入口

frontend/                PyQt6 界面
  theme.py               配色与全局样式表
  widgets/               自定义控件
    rack_view.py         机柜正视图（自绘 + 拖拽）
    rack_export.py       PNG / PDF 导出（复用同一套绘制代码）
    device_table.py      设备表格模型
    unracked_list.py     待上架列表（拖拽源）
    common.py            卡片、统计块、占用条
  dialogs/               各类编辑对话框
    device_type_dialog.py  设备类型编辑（色板 + 预览）与带「＋ 新增类型」的下拉
  pages/                 七个页面（类型清单管理在「设置」页）
  main_window.py         导航与页面联动
  app.py                 启动装配

tests/
  test_backend.py        后端逻辑，190 个用例
  test_gui.py            GUI 冒烟，160 个用例（离屏运行）

tools/
  make_icon.py           生成 app.ico，机柜正视图，配色取自 constants
assets/
  app.ico                应用图标，8 档尺寸 16 到 256
build.spec               PyInstaller 打包配置
```

前端只调 `backend.Backend` 的方法，拿到的都是 dataclass。后端不 import 任何 Qt 模块，所以能脱离界面单独跑测试；将来要加 HTTP 层或换存储，只需再实现一份同样签名的门面。

设备类型是唯一一份可变的「常量」：清单存在库里，打开或切换数据库时由 `DeviceTypeService` 灌进 `constants.DEVICE_TYPES` 和 `DEVICE_TYPE_COLORS`。这两个容器被十来处按值导入（`from .constants import DEVICE_TYPES`），所以刷新只能就地改 —— 切片赋值和 `clear()` + `update()`，不能整体重新绑定，否则导入方还拿着旧对象。绘图代码统一走 `constants.type_color()` 取色，认不出的类型给中性灰。

## 测试

```bash
python tests/test_backend.py
python tests/test_gui.py
```

后端测试覆盖 U 位冲突拦截（重叠、越界、非法值）、自动找位与批量上架、机柜总高保护、删除机柜时设备转未上架、容量汇总与超限判定、Excel 预检与往返导入导出、备份与切库、设备类型的增删改与兜底规则，以及老库（没有 `device_type` 表）升级后清单与台账仍然对得上。GUI 测试离屏跑起真实窗口，逐页切换、模拟拖拽落位、验证坐标换算与导出文件，并盯住类型这两条链路：设置页加了类型之后台账筛选下拉和机柜图配色要跟着变；设备对话框里点「＋ 新增类型…」要能当场加完、自动选上、直接用它存设备，取消时下拉退回原来的选项。

## 几个约定

- **U 位编号**：从机柜底部往上数，1U 最下面。这是机房里的标准做法。
- **已下架的设备不占 U 位**，所以可以和别的设备位置重叠，方便记录历史。
- **删机柜或机房不会删设备**，柜内设备自动转为「待上架」，避免误删台账。
- **有机柜但没填 U 位的设备**也算待上架，会出现在待上架列表里，不会卡在中间状态看不见。
- **删设备类型不会删设备**，那些设备归到「其他」；「其他」本身不能删也不能改名，识别不出的类型都要有地方归。
- **设备类型跟着 .db 文件走**，属于配置而不是台账，所以「清空所有数据」不会动它。
